## 二、实现清单

### 后端

| 能力 | 实现 |
|---|---|
| 评论列表 | `GET /api/comment/page`，顶层评论分页（新的在前），回复挂在 `children` 下 |
| 发表评论 / 回复 | `POST /api/comment`，登录校验；回复可指向任意评论，展示时归位到顶层并带“回复 @某人” |
| 删除评论 | `DELETE /api/comment/{id}`，作者本人或 ADMIN；递归逻辑删除全部后代 |
| 评论限流 | 同一用户每分钟最多 5 条（Redis `blog:comment:rate:{userId}`，60s 过期） |
| 禁用用户 | 评论时二次校验 `user.status`，禁用账号返回 403（PRD 假设 6） |
| 点赞切换 | `POST /api/like/article/{id}`，`article_like` 唯一约束 `uk_article_user` 防重复 |
| 点赞数 | `blog:like:count:{id}` 缓存，TTL 10 分钟；未命中查 `article_like` 并回填；同步维护 `article.like_count` |
| 阅读量 | 详情接口 `INCR blog:view:{id}`；`ViewCountSyncTask` 每 5 分钟累加回 `article.view_count` 并删 key |
| 降级 | Redis 故障：阅读量直接写库、点赞数查库、评论限流放行，主链路不中断 |

关键类：

- `config/ViewCountSyncTask.java`
- `service/impl/ArticleServiceImpl.java`（详情阅读量 + 点赞状态聚合）

## 五、踩坑记录

| 现象 | 原因与处理 |
|---|---|
| 点赞/阅读量读取抛序列化异常 | `RedisTemplate<String,Object>` 默认 JDK 序列化与 `INCR` 写入的纯数字字符串不兼容，统一改用 `StringRedisTemplate` |
| 两条评论排序不稳定 | `create_time` 为秒级精度，同秒插入顺序不定；增加 `id` 作为次级排序 |
| 启动报 `Flexible Constructor Bodies ... source level 25` | IDE 的 JDT 自动构建把半成品 class 写进 `target/classes`；把 `clean compile && spring-boot:run` 串成一条命令执行 |
| Vite 打包报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` | 沙箱拦截批量删除，Vite 清空旧 `dist/assets` 触发；先把 `dist` 移走再 `npx vite build` |
| 评论区删除无弹窗 | `App.vue` 缺少 `n-dialog-provider`，已补上 |
